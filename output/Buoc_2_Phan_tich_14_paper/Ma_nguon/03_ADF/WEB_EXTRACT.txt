L164: # ADF_framework
L165: 
L166: ADF is a novel news recommendation framework, intended to provide fair, diverse, and accurate recommendations. ADF is thus designed to promote users' awareness, through diversity, while not orienting users' main interests or opinions, through fairness. This repository contains the code to run the proposed framework on the MIND and Adressa datasets.
L167: 
L168: The different steps of ADF are the following:
L169: 
L170: Here is the organization of the code:
L171:   * data: contains all necessary data files for both Adressa and MIND datasets.
L172:   * reco_scores_baseline: contains the list of relevance scores for all recommendation models (centroidVector, LSTUR, NAML, NPA, NRMS). Please note that news centroidVector was applied using the 【83†ClayRS library】, while deep-learning models were applied using the 【84†NewsRecLib library】. To ensure reproducibility, we detail below how these libraries were used to compute the recommendation scores.
L173:   * re_ranking: contains the python files to apply the re-ranking approaches. Different ways to re-rank recommendations are included:
L174:     * Greeedy re-ranking (greedy.py): serve as baseline.
L175:     * ADF (ADF.py): proposed approach, fairness-constrained diversification, with personalization of the target diversity.
L176:   * reco_scores_ADF: contains the re-ranking list of recommendations when ADF is applied.
L177:   * reco_scores_greedy: contains the re-ranking list of recommendations when the greedy diversification is applied.
L178:   * evaluation: contains a notebook necessary to evaluate the outputs of the models (baselines and ADF).
L179: N.B: Please note that some files are too large to be uploaded on the GitHub repository
L180: # Apply baseline recommendation models
L181: ## NewsRecLib
L182: First, we used the NewsRecLib library to compute recommendation scores for the LSTUR, NAML, NPA, and NRMS models. All models were run with their default settings; we did not modify any parameters in the configuration files. The only change we made was to enable the saving of recommendation lists by setting`save_recs: False` in each model’s YAML configuration file (【85†LSTUR】, 【86†NAML】, 【87†NPA】, 【88†NRMS】).
L183: The saved recommendation lists are unranked and include all candidate items along with their associated scores. We then followed the library’s instructions and executed the following commands:
L184: 
L185:     `#LSTUR
L186:     python newsreclib/train.py experiment=lsturcon_adressaoneweek_pretrainedemb_celoss_bertsent
L187:     python newsreclib/train.py experiment=lsturcon_mindsmall_pretrainedemb_celoss_bertsent
L188: 
L189:     #NAML

L201: ## ClayRS
L202: 
L203: The ClayRS library is organized into three interdependent modules: content analyzer, recommender system, and evaluation. For our experiments, to ensure consistent data usage across all recommendation models, we reused the data splits and news representations produced by NewsRecLib and applied the CentroidVector model using only the recommender system module of ClayRS.
L204: To apply CentroidVector, we downloaded and formatted the required data according to the 【89†library's documentation†swapuniba.github.io】.
L205: We then instantiated and executed the recommender system, specifying the necessary parameters such as the similarity measure, the training set, and the path to the news representations. We set a large recommendation list size (n = 1000) to ensure that enough items were retrieved to support our ADF framework.
